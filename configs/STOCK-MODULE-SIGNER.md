# Original GKI module signer

Public certificate only, extracted from the untouched NP05J ROM10.5.11 boot image.

- Stock boot SHA256: `0cbd8790e254a54a186caea136d8c1ecd31005bba73826619d6c457658f76caf`
- Kernel offset inside boot: 4096; certificate offset inside kernel: 33590016; DER length: 1357
- DER SHA256: `46a87b2eeaf96989c0e9a59b5f26e133a1cdf984bac30f874a3266756f2974b3`
- Subject/issuer: `CN=Build time autogenerated kernel key`
- Serial: `507c403f5d813833f3255b1d5996acd99f250bbf`

Observed prior candidate failure: stock rfkill.ko rejected with `rfkill: exports protected symbol rfkill_alloc`. This prevented btpower and Bluetooth audio dependencies from registering, deferring the entire sound card and blocking Android startup in the audio initialization path.

The original rfkill.ko detached PKCS7 signature was cryptographically verified locally using this certificate (`openssl cms -verify -binary ... -certfile ... -noverify`: CMS Verification successful). `-noverify` skips external CA chain validation, not content signature verification; trust anchor provenance is the pinned original boot.

The build adds this public certificate using CONFIG_SYSTEM_TRUSTED_KEYS. It retains CONFIG_MODULE_SIG, CONFIG_MODULE_SIG_PROTECT, CONFIG_MODVERSIONS, RFKILL=m, and the separate generated build signing key. No OEM private key is present or required. No system/vendor module replacement or signature-check bypass is performed. Tests pin certificate bytes; CI also checks the final raw Image contains the DER certificate.

This is a targeted experimental fix, not proof of complete module ABI or successful device startup. Recheck boot and module errors after compiling and validating the next candidate.
